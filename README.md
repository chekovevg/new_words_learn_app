# New Words Learn App

Личный словарь на Vite + Supabase. У каждого пользователя свой аккаунт, свой список слов, свой прогресс и отдельная админ-логика.

## Возможности

- вход и регистрация по email/password;
- профили с именем;
- личный список слов для каждого пользователя;
- отметка `выучено` с сохранением в Supabase;
- поиск, фильтр по статусу, уровню и языку;
- ручное добавление слов;
- импорт из Excel/CSV без удаления текущих слов;
- админ-панель для просмотра пользователей и управления ими.

## Что нужно указать в `.env.local`

Создай файл `.env.local` в корне проекта:

```env
VITE_SUPABASE_URL=https://YOUR-PROJECT.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
```

Публичный ключ Supabase можно брать из Dashboard. `service_role` в фронтенд не добавляй.

## Локальный запуск

```bash
npm install
npm run dev
```

Если запускаешь в первый раз, сначала применить SQL из `supabase/migrations/20260526_init.sql` в Supabase.

## База данных

SQL-миграция создаёт:

- `profiles` - профиль пользователя;
- `words` - личные слова пользователя;
- политики RLS;
- триггер на создание профиля после регистрации;
- RPC-функции для админки.

Чтобы включить админку для своего аккаунта, после первой регистрации поставь своему профилю `role = admin` в таблице `profiles`.

## Как работает миграция старых слов

Если в браузере осталась старая локальная версия, после входа появится баннер с импортом текущего списка слов в аккаунт Supabase.

Это переносит:

- слова из текущего seed-списка;
- отметки `learned` из старого `localStorage`.

## Как добавлять слова

Есть два пути:

1. вручную через форму `Добавить слово`;
2. импортом Excel/CSV через форму `Импорт`.

Импорт работает в режиме `merge`: совпадающие слова обновляются, новые добавляются, текущий список не очищается.

## Как обновлять список слов

1. Внеси изменения в источник данных, если нужен новый seed для миграции.
2. Если нужно обновить SQL-схему, правь `supabase/migrations/20260526_init.sql`.
3. После этого протестируй локально и сделай `build`.

## Как опубликовать

Проект готов для GitHub Pages.

Скрипт сборки:

```bash
npm run build
```

Если используешь GitHub Actions, проверь, что Pages смотрит на workflow-деплой. Для branch-based Pages используется `base: './'`.

## Что проверить руками

- регистрация и вход;
- сохранение имени профиля;
- загрузка личного списка слов после входа;
- переключение `выучено / не выучено`;
- импорт Excel без удаления текущих слов;
- ручное добавление слова;
- админ-панель у пользователя с ролью `admin`;
- синхронизацию на десктопе и телефоне под одним аккаунтом.
## AI enrichment

The app can call Gemini from a serverless Vercel function to enrich missing `level` and `example` fields.
Set these environment variables on Vercel:

```env
GEMINI_API_KEY=your_gemini_key
GEMINI_MODEL=gemini-2.5-flash
```
